# QCHAN v4.0.0 gallery linked-view source hotfix R3

## Observed failure

The corrected R2 cohort run completed with at least eight unique deterministic
Panel G examples, and the cohort manifest advanced beyond the gallery-count
gate. The review packager then stopped on the first gallery source CSV because
the source-data schema did not contain the required `view` field:

- `waveform`
- `spectrogram`
- `target_ltas`
- `reference_ltas`
- `ltas_difference`

The notebook had saved equivalent data under the older `row_type` schema:
`waveform`, `spectrogram`, and a single combined `ltas` row type containing
target, reference, and difference columns. The plotted figure was present, but
the source CSV did not explicitly identify the five linked views required by
the standardized figure contract.

## Scientific assessment

This is a source-data contract defect, not a measurement or plotting failure.

It does not affect:

- the four QCHAN feature definitions;
- any of the 519 target spectra;
- any leave-one-subject-out reference;
- any recording-level QCHAN value;
- reference membership or vintage;
- target or reference robustness;
- the deterministic gallery identities;
- the visible waveform, spectrogram, LTAS, or difference panels.

All gallery examples generated by R2 share the older source schema, so all must
be regenerated rather than patching only the first example reported by the
packager.

## R3 correction

R3 introduces a canonical long-form Panel G source-data contract.

Every gallery source CSV now explicitly contains a `view` column with all five
required identities. Target LTAS, reference LTAS, and their difference are
stored as separate linked views with a common `linked_value` ordinate. The
legacy measurement columns remain present for traceability.

For an unavailable reference-relative example, the three LTAS view identities
remain present as explicit placeholder rows with:

- `view_available = False`
- a declared `view_unavailable_reason`
- no fabricated spectral value

The notebook now records linked-view completeness per gallery item, adds a G7
check requiring every example to contain all five view identities, and includes
that requirement in `cohort_evidence_complete`.

## Versioning

The measurement remains `qchan-v4.0.0-candidate`.

Only the cohort orchestration/source-data contract advances:

- orchestration: `qchan-v4.0.0-cohort-orchestration-v3`
- hotfix revision: `gallery-linked-source-r3`
- gallery source contract: `five_explicit_linked_views_v1`

No numerical extraction, reference construction, estimator parameter, support
rule, checklist requirement, or figure-content requirement was weakened.
